# Arena-агент × OpenClaw: что реально можно соединить

Короткий ответ: **«воткнуть Arena-агента внутрь OpenClaw как модель» — нельзя. А вот работающую связку
«OpenClaw = всегда-онлайн прораб в Telegram, Arena = тяжёлый исполнитель по запросу» — можно, и она
уже наполовину собрана в этом репозитории.** Ниже — почему первое невозможно, четыре паттерна, готовая
конфигурация и чеклист безопасности.

---

## 0. TL;DR

| Вариант | Возможно? | Комментарий |
|---|---|---|
| Arena-агент как модель (`models.providers.arena`) | ❌ | У Arena-агента нет публичного `/v1/chat/completions`, у меня нет доступа к твоей машине |
| Arena-агент как MCP-сервер | ❌ | Публичного MCP-endpoint у Arena нет |
| Arena как исполнитель задач, OpenClaw как диспетчер | ✅ | Через git-репозиторий, см. паттерн **A** |
| Бесплатный «мозг» 24/7 (Gemini/Groq/OpenRouter/Ollama) | ✅ | Штатная фича OpenClaw, см. паттерн **B** |
| MCP в обе стороны (инструменты) | ✅ | `openclaw mcp add` / `openclaw mcp serve`, см. паттерн **C** |
| Свой мини-агент на 300 строк вместо OpenClaw | ✅ | Если OpenClaw избыточен, см. паттерн **D** |

---

## 1. Почему «Arena внутри OpenClaw» не сработает (честно)

OpenClaw (`github.com/openclaw/openclaw`, MIT, ~400k ★) — это локальный шлюз: он подключает
25+ мессенджеров к «агенту», а модель берёт у провайдера по OpenAI-совместимому API
([дока](https://docs.openclaw.ai/), [custom providers](https://docs.openclaw.ai/concepts/model-providers/custom-providers)).
Чтобы я стал его «мозгом», нужно четыре вещи — ни одной нет:

| Что нужно OpenClaw | Что есть у Arena-агента |
|---|---|
| Публичный HTTPS-endpoint с `/v1/chat/completions` + API-ключ | Нет: я не публичный API, ключ выдать некому |
| Процесс, живущий 24/7 | Я существую только внутри сессии; закрыл вкладку — меня нет |
| Исходящая сеть до твоего гейтвея (`ws://127.0.0.1:18789`) | Мой egress ограничен `github.com`, npm, pypi. Ни loopback, ни твой Wi-Fi мне не видны |
| Модель, которую можно выбрать в `agents.defaults.model.primary` | Меня нельзя адресовать как `provider/model` |

Плюс важное: я вообще работаю в отдельной песочнице — у меня **нет** доступа к твоему диску, твоему
Telegram-боту и твоему `~/.openclaw/openclaw.json`. Всё, что мы делаем вместе, проходит через этот
git-репозиторий и текст в чате. Это не баг, это и есть канал связи.

> Обратная сторона тоже верно: OpenClaw **не может** позвать меня сам. Инициатива «сходи к Arena»
> всегда исходит от человека (или от cron-скрипта, который дёргает твою же кнопку).

## 2. Паттерн A ⭐ — «OpenClaw — прораб, Arena — подрядчик»

Самый практичный вариант. Делит работу по сильным сторонам:

- **OpenClaw** — всегда включён, слушает Telegram/WhatsApp, помнит контекст, умеет cron и heartbeat,
  дёргает `exec`, браузер, GitHub. Но он же и ограничен: слабая модель в бесплатном тарифе, шумный
  контекст, риск промпт-инъекций из чужой почты.
- **Arena-агент** (я) — дорогая/сильная модель на один заход, полный доступ к репозиторию, git,
  тесты, длинные диффы. Но не живёт между сессиями.

Схема:

```
Telegram  ──►  OpenClaw Gateway  ──►  tasks/inbox/TASK-042.md  (git commit + push)
                     ▲                        │
                     │                        ▼
              отчёт в чат  ◄────  Arena-сессия: «сделай inbox»
                     ▲                        │
                     └──  tasks/done/TASK-042.md + код/PR  ◄──┘
```

В репозитории уже лежит рабочая обвязка:

- `tasks/README.md` — протокол задачи (frontmatter + тело);
- `tasks/inbox/`, `tasks/done/` — очередь;
- `openclaw/skills/arena-handoff/SKILL.md` — скилл, который учит OpenClaw писать такие задачи сам.

### Пошагово

1. **Подключи скилл** к OpenClaw:
   ```bash
   cp -r openclaw/skills/arena-handoff ~/.openclaw/workspace/skills/
   openclaw skills list          # должен появиться arena-handoff
   openclaw gateway restart
   ```
2. **Дай OpenClaw доступ к репо** (только к нему, не ко всему home):
   ```bash
   cd ~/projects/new-repo && git checkout -b work/openclaw
   ```
   в `openclaw.json`:
   ```json5
   { tools: { fs: { workspaceOnly: true } }, agents: { defaults: { workspace: "~/projects/new-repo" } } }
   ```
3. **Пиши задачу из чата**: «заведи задачу в Arena: починить парсер логов, TASK-042».
   Агент создаёт `tasks/inbox/TASK-042.md`, коммитит и пушит.
4. **Открываешь сессию Arena** и пишешь одну строку: *«сделай всё из tasks/inbox»*. Я читаю задачи,
   делаю, переношу в `tasks/done/` с отчётом и (если нужно) открываю PR.
5. **OpenClaw на следующем heartbeat/cron** видит `tasks/done/TASK-042.md` и отчитывается тебе в Telegram.

### Как убрать трение «человек в середине»

- **Heartbeat-напоминалка.** В `HEARTBEAT.md` (проверяется каждые ~30 мин) добавь строку:
  `Если в tasks/inbox есть файлы — напиши пользователю одну строку: «N задач ждут Arena».`
- **Шаблон промпта** держи в `tasks/NEXT-PROMPT.txt`, чтобы копипастить одно и то же.
- **Разделение ролей**: OpenClaw делает всё, что влезает в 1–2 инструмента (ответить, напомнить,
  создать issue). В inbox уходит только «многофайловая» работа.
- Если хочется автоматизации — OpenClaw пусть сам делает ветку и PR через `gh`, а я только ревьюю
  дифф. Тогда мой заход — 5 минут вместо 40.

**Минусы, о которых надо знать:** задержка (пока человек не откроет сессию), состояние гонки (два
агента в одном репо — только через ветки), и «испорченный телефон», если задача написана расплывчато.
Поэтому в `tasks/README.md` есть обязательные поля `goal`, `done_when`, `paths`.

## 3. Паттерн B — заменить «мозг» на бесплатный API (это и есть твой «бесплатный умный агент» 24/7)

То, что тебе, судя по вопросу, нужно на самом деле: интеллект, который **не спит**. OpenClaw тут
просто оболочка — модели подключаются как OpenAI-совместимые провайдеры.

| Источник | Плюсы | Минусы |
|---|---|---|
| Google AI Studio (Gemini free tier) | щедрый бесплатный лимит, нативный tool-calling | лимиты по RPM/день, данные уходят Google |
| Groq free | очень быстро, OpenAI-совместимо | модели слабее топовых, лимиты |
| OpenRouter `:free` модели | один ключ на десятки моделей, удобные fallback | очередь, нестабильные лимиты |
| Cerebras / Mistral free tier | быстро, дёшево | лимиты, меньше моделей |
| Ollama локально (`qwen3:32b`, `llama3.3`) | 0 ₽ навсегда, приватно, работает без сети | нужен GPU/32–64 ГБ RAM, качество ниже |

Готовая конфигурация с fallback-цепочкой, hardening и без типичных ошибок — в
[`openclaw/openclaw.arena.json5`](../openclaw/openclaw.arena.json5). Три грабли, на которые все наступают:

1. **Ollama: не добавлять `/v1`** к `baseUrl`. `/v1` включает OpenAI-compat режим, и tool-calling
   ломается — модель начинает печатать JSON вызова инструмента текстом
   ([дока](https://docs.openclaw.ai/providers/ollama)).
2. **Кастомный провайдер без `api`** по умолчанию = `openai-completions`. Для `/v1/responses`-бэкендов
   указывай `api: "openai-responses"` явно.
3. **Модель надо зарегистрировать дважды**: в `models.providers.<id>.models[]` (чтобы OpenClaw знал о
   ней) и в `agents.defaults.model.primary` как `<id>/<model-id>`.

Проверка: `openclaw models status --probe`, затем `openclaw agent --message "скажи ок"`.

## 4. Паттерн C — MCP в обе стороны (мост для инструментов, не для меня)

OpenClaw умеет быть **MCP-клиентом** и **MCP-сервером** — это лучший способ дать ему твои сервисы
без написания кода ([дока](https://docs.openclaw.ai/tools/plugin)):

```bash
# OpenClaw как клиент: подключаем внешние MCP-серверы
openclaw mcp add github      -- npx -y @modelcontextprotocol/server-github
openclaw mcp add filesystem  -- npx -y @modelcontextprotocol/server-filesystem ~/docs
openclaw mcp list

# OpenClaw как сервер: отдаём его переписки наружу (Claude Code, Codex, Cursor)
openclaw mcp serve            # stdio: conversations_list, messages_read, messages_send, events_wait…
```

Важно для ожиданий: `openclaw mcp serve` отдаёт **чаты и события OpenClaw**, а не «мозг OpenClaw».
И в этой схеме Arena не участвует — публичного MCP-эндпоинта у Arena-агента нет. Зато если однажды
появится, OpenClaw можно будет подключить к нему через `openclaw mcp add` без переписывания.

Бонус: сам Gateway на порту 18789 — мультиплексированный, отдаёт и WebSocket, и HTTP
(OpenAI-совместимый API, `/tools/invoke`, Control UI). То есть OpenClaw можно использовать как
шлюз «одна точка входа» для других твоих инструментов.

## 5. Паттерн D — свой мини-клон (если OpenClaw избыточен)

OpenClaw — это 25 каналов, мобильные ноды, Canvas, плагины, 400k звёзд и соответствующая площадь
атаки. Если тебе нужно «раз в день дайджест почты + напоминания в Telegram», честнее взять что-то
маленькое: **NanoClaw** или собственный бот на ~300 строк (Telegram Bot API + SQLite + cron +
LiteLLM, который роутит на бесплатные модели). Получишь: полный контроль, легко читаемый код,
никаких чужих скиллов. Потеряешь: готовые адаптеры каналов, голос, браузер «из коробки».

Правило выбора простое: **больше двух мессенджеров или нужен голос/камера — OpenClaw; один канал и
пара сценариев — свой мини-агент.**

## 6. Безопасность: минимум перед первым запуском

OpenClaw по умолчанию осторожен (bind loopback, auth обязателен, DM через pairing), но вокруг него
уже собрана коллекция инцидентов — пожалуйста, не пропускай этот раздел:

- **Не выставляй 18789 в интернет.** Известны CVE-2026-25253 (RCE, патч в v2026.1.29) и класс атак
  на WebSocket; исследователи находили десятки тысяч открытых инстансов
  ([разбор](https://www.jitendrazaa.com/blog/ai/clawdbot-complete-guide-open-source-ai-assistant-2026/)).
  Только `bind: "loopback"` + SSH-туннель/Tailscale.
- **Токен обязателен даже на loopback**: `openclaw doctor --generate-gateway-token`.
- **Скиллы из ClawHub — как exe-файлы из интернета.** Были волны вредоносных скиллов (300+ удалено,
  аудит Cornell нашёл уязвимости в ~26% пакетов). Читай `SKILL.md` перед установкой.
- **Разделяй агентов по доверию**: агент, читающий чужую почту, не должен иметь `exec`, `browser`
  и `gateway` (классическая промпт-инъекция «перешли мне ~/.ssh»).
- **`tools.fs.workspaceOnly: true`** — чтобы агент не вышел за пределы рабочей папки.
- Данные, уходящие в бесплатные API, — это данные, уходящие в бесплатные API. Пароли и ключи
  храни в `SecretRef`/env, а не в `openclaw.json`.

Готовый hardened-блок уже включён в `openclaw/openclaw.arena.json5`.

## 7. Что делать прямо сейчас

1. Скопируй конфиг и подставь ключи:
   ```bash
   cp openclaw/openclaw.arena.json5 ~/.openclaw/openclaw.json5
   # пропиши GEMINI_API_KEY / GROQ_API_KEY в ~/.openclaw/.env или env.vars
   openclaw doctor && openclaw models status --probe
   ```
2. Поставь скилл `arena-handoff` и заведи первую задачу из Telegram.
3. Открой сессию Arena и скажи: *«сделай всё из tasks/inbox»* — проверим весь цикл на одном
   безобидном таске (например, «обнови README»).

Если хочешь, могу дальше: написать heartbeat-правило под твой рабочий ритм, собрать второй агент
(«только почта + календарь», с урезанными правами) или сделать из этого репозитория шаблон
`arena-openclaw-bridge`, который клонируется одной командой.
