# 4 ГБ ОЗУ + бесплатный Colab + Google Drive: что реально работает

Продолжение [`arena-x-openclaw.md`](./arena-x-openclaw.md). Здесь — только про железо и хостинг.

## TL;DR

1. **Google Colab не подходит как хостинг гейтвея.** Не из-за мощности, а из-за модели использования:
   максимум 12 ч на сессию, отключение при простое, эфемерный диск, нет постоянного входящего адреса.
   Бот, который оживает только когда у тебя открыта вкладка, — это не «всегда-онлайн ассистент».
2. **4 ГБ ОЗУ — не проблема.** Гейтвей OpenClaw в простое ест 200–400 МБ (официальный минимум — 1 ГБ,
   рекомендация 2 ГБ). Твоё ограничение — **аптайм**, а не память: закрыл ноут — бот умер.
3. **Бесплатный «мозг» не надо запускать локально вообще.** Gemini AI Studio / Groq / OpenRouter free —
   это hosted API: ни RAM, ни GPU, ни туннелей. Colab нужен только чтобы один раз проверить ключи и
   собрать конфиг (ноутбук ниже).
4. **Drive — это бэкап, а не рабочая папка.** rclone + tar раз в сутки; монтировать Drive как
   `~/.openclaw` нельзя (I/O-ошибки и таймауты при большом числе файлов — прямо в FAQ Colab).
5. Если нужен настоящий 24/7 — бесплатный ARM-VPS (Oracle, нюансы ниже) + бэкап в Drive + ноут как
   тонкий клиент.

## 1. Почему Colab — не хостинг (по фактам, не по ощущениям)

| Ограничение | Что значит для OpenClaw |
|---|---|
| Не более 12 ч на сессию ([FAQ](https://research.google.com/colaboratory/faq.html)) | Гейтвей умрёт посреди ночи, cron/heartbeat не сработают |
| Простой → рантайм убивают | Перестал писать боту на час — VM нет |
| Диск эфемерный, Drive монтируется отдельно | `~/.openclaw` (сессии, память, скиллы) стирается при каждом перезапуске |
| Нет стабильного входящего порта | Нужен туннель (cloudflared/ngrok), URL меняется при каждом старте → конфиг переписывать руками |
| Free-рантайм часто CPU-only | 7–8B модель на CPU — секунды на токен, для агентского цикла неюзабельно |
| Colab рассчитан на интерактивные вычисления | Постоянный сервис = риск троттлинга/бана аккаунта |

Вывод: Colab годится для **разовых задач**, а не для дежурства.

## 2. Три рабочие схемы для слабого ноутбука

### A. Гейтвей на бесплатном VPS, ноут — только терминал ⭐

```
Telegram ⇄ VPS (гейтвей, 200–400 МБ) ⇄ hosted brain (Gemini/Groq/OpenRouter)
                 │
                 └── ежедневный бэкап → Google Drive
ноут: браузер + Control UI (или просто Telegram с телефона)
```

**Oracle Cloud Always Free** — самый жирный вариант, но в 2026-м его урезали, и об этом мало кто знает:

- ARM Ampere A1: было 4 OCPU / 24 ГБ, стало **2 OCPU / 12 ГБ** на tenancy (1 500 OCPU-часов +
  9 000 ГБ-часов в месяц). Изменение появилось в доках ~15 июня 2026, принудительно с 18 августа 2026
  ([официальные лимиты](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)).
- **Idle reclaim**: если за 7 дней 95-й перцентиль CPU < 20 %, сеть < 20 % и память < 20 % — инстанс
  могут остановить. Спящий бот как раз под это попадает.
  Лечится апгрейдом аккаунта до Pay As You Go: в пределах Always Free по-прежнему $0, а правило
  reclaim на PAYG не действует (но нужна карта).
- 12 ГБ и 2 ядра для нашего гейтвея — с запасом в 20 раз. Docker-песочница и браузерный сайдкар тоже
  влезут.

Альтернативы, если Oracle не даёт инстанс (это бывает из-за нехватки ёмкости): любой микро-VPS за
$3–5, Google Cloud Shell (бесплатно, 5 ГБ persistent home, но сессия ~12 ч и нет входящего трафика),
Hugging Face Spaces (бесплатный Docker Space, засыпает при простое). Все три — с оговорками; Oracle
всё же лучший «бесплатный и постоянный».

### B. Ноут всё-таки хостит (это допустимо)

На 4 ГБ это работает, если не тащить тяжёлое:

- гейтвей без Docker-песочницы и **без browser-скиллов** (Chromium + Xvfb — это +0.5–2 ГБ);
- один агент, один канал (Telegram), модель — hosted;
- Chrome с десятком вкладок придётся подрезать: Node + браузер + ОС на 4 ГБ — впритык;
- `tools.exec` оставить выключенным — он не про память, а про риск.

Плюс: ноль инфраструктуры. Минус: пока ноут спит — бот мёртв (heartbeat, cron, ответы — всё стоит).

### C. Без сервера вообще

Только WebChat (Control UI на `127.0.0.1:18789`) по требованию + hosted brain. Проактивности нет,
но «спросить и получить ответ с инструментами» работает, и это 0 ₽ и 0 обслуживания. Хороший режим,
чтобы понять, нужен ли вообще вариант A.

## 3. Бесплатный «мозг»: что выбрать при 4 ГБ

| Провайдер | Ключ | Сильная сторона | Слабая сторона |
|---|---|---|---|
| Google AI Studio (Gemini) | `GEMINI_API_KEY` | самый щедрый free tier, нативный tool-calling | дневные лимиты, данные уходят Google |
| Groq | `GROQ_API_KEY` | очень быстро, OpenAI-совместимо | модели среднего класса, лимиты RPM |
| OpenRouter `:free` | `OPENROUTER_API_KEY` | один ключ → десятки моделей, удобные fallback | очередь, нестабильные лимиты |
| Cerebras / Mistral | свои | быстро и бесплатно на старте | мало моделей |
| Cloudflare Workers AI | аккаунт CF | бесплатный дневной лимит, без карты | не всё умеет tool-calling |

Практика: держи **два** провайдера в fallback-цепочке. Когда у первого кончился дневной лимит,
OpenClaw молча переключится, а не «сломается». Конфиг — в [`../openclaw/openclaw.json`](../openclaw/openclaw.json).

Проверка после настройки:

```bash
openclaw models status --probe     # покажет, какие ключи живы и какие модели ответили
openclaw agent --message "скажи ок"
```

## 4. Google Drive: как делать правильно

**Что нельзя:** `rclone mount` Drive в `~/.openclaw` или в workspace. Drive — не POSIX-ФС: тысячи
мелких файлов (сессии, JSONL) дают `Input/output error` и таймауты; в FAQ Colab это описано прямо.
Плюс токены гейтвея окажутся в чужом облаке в открытом виде.

**Что можно:** ежедневный архив + шифрование + ротация. Готовый скрипт:
[`../scripts/backup-openclaw-to-drive.sh`](../scripts/backup-openclaw-to-drive.sh).

```bash
# один раз
sudo apt install rclone age          # или brew install rclone age
rclone config                        # new remote → drive → OAuth в браузере
# каждый день (cron на VPS)
0 4 * * * ~/bin/backup-openclaw-to-drive.sh >> ~/backup.log 2>&1
```

Скрипт кладёт `openclaw-YYYY-MM-DD.tar.gz.age` в `gdrive:openclaw-backups/`, проверяет, что архив
не пустой, и удаляет всё старше 7 дней. Восстановление:

```bash
age -d -i ~/.age/openclaw.key openclaw-2026-10-26.tar.gz.age | tar -xzf - -C ~
openclaw doctor --fix && openclaw gateway restart
```

## 5. Colab: что в нём делать полезного

Ноутбук [`../notebooks/colab_free_brain.ipynb`](../notebooks/colab_free_brain.ipynb) — запускается за
минуту, GPU не нужен:

1. **Проверка окружения** (RAM, GPU) — чтобы не гадать, что тебе выдали.
2. **Тест ключей с настоящим tool-calling.** Не «ответил ли чат», а «вернул ли модель `tool_calls`» —
   OpenClaw без инструментов бесполезен, а половина «бесплатных» эндпоинтов их не умеет.
3. **Генератор конфига**: печатает готовый json5-блок `models.providers` + `agents.defaults.model`
   только для тех провайдеров, которые реально ответили — копируешь и вставляешь в `openclaw.json`.
4. **Экспериментальная секция**: Ollama + cloudflared quick tunnel прямо в Colab → получаешь
   `baseUrl` вида `https://xxx.trycloudflare.com/v1` для локальной модели. Работает, но живёт до
   перезапуска рантайма — только для тестов, не для дежурства.
