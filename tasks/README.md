# tasks/ — очередь задач между OpenClaw и Arena-агентом

Один файл = одна задача. OpenClaw (или человек) кладёт задачу в `inbox/`, Arena-сессия переносит её
в `done/` с отчётом. Никаких секретов в задачах.

## Жизненный цикл

```
tasks/inbox/TASK-042.md   →  Arena берёт в работу  →  tasks/done/TASK-042.md (+ код/PR)
```

- `inbox/` — только новые, ещё не сделанные задачи. Разбирать по возрастанию номера.
- `done/` — закрытые. Файл не удаляется никогда (это журнал).
- Номер выдаётся по порядку: следующий = максимальный существующий + 1.

## Формат файла

```markdown
---
id: TASK-042
title: Починить парсер access-логов
created: 2026-10-26
created_by: openclaw        # openclaw | human
priority: normal            # low | normal | high
status: todo                # todo | in-progress | blocked | done | cancelled
goal: Парсер падает на строках с IPv6-адресом.
done_when: pytest tests/test_parser.py -q зелёный и есть кейс с IPv6.
paths: src/parser.py, tests/test_parser.py
constraints: без новых зависимостей; не менять публичный API парсера.
---

## Context

Что известно: пример строки лога, traceback, гипотеза, ссылки на issue.
Если контекста нет — честно пиши «неизвестно», а не выдумывай.

## Result  <!-- заполняется агентом Arena при переносе в done/ -->

- status: done
- changed: src/parser.py, tests/test_parser.py
- commit: <sha> / PR #<n>
- notes: что осталось, что требует решения человека
```

## Правила для Arena-сессии

1. Прочитай все файлы в `inbox/`, начни с наибольшего `priority`, затем с меньшего номера.
2. Если `done_when` не проверяем или противоречив — не гадай: `status: blocked` + вопрос в отчёте.
3. Выполняй в отдельной ветке (`task/TASK-042`), если задача меняет код. Конфиги и доки можно в `main`.
4. Переноси файл в `done/` **тем же коммитом**, что и изменения, — история не должна расходиться.
5. Отчёт: 2–4 пункта, без пересказа диффа целиком.

## Правила для OpenClaw

- Проверяй `inbox/` на heartbeat и один раз напоминай: «N задач ждут Arena».
- Не создавай задачу, если хватает одного инструмента.
- Не правь код сам, если задача уже в `inbox/` — иначе получится конфликт правок.
